# CAN

CAN 总线常用在汽车和工业设备上。芯片的引脚不能直接接到总线上，中间要接一个收发器芯片，比如 TJA1050。

```python
from stmpy import CAN, delay_ms

bus = CAN(bitrate=500_000)
data = bytearray(8)

def main():
    while True:
        data[0] += 1
        bus.send(0x123, data)       # 放进发送邮箱，立刻返回

        while bus.available():
            who = bus.id()          # 先看是谁发的，消息还留着
            n = bus.read(data)      # 取走消息，返回长度
        delay_ms(100)
```

用中断接收：

```python
@bus.on_rx()
def on_message():
    while bus.available():
        who = bus.id()
        n = bus.read(data)
```

## 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `bitrate` | 500_000 | 波特率，最高 1_000_000。总线上所有节点必须一致 |
| `tx` | `""` | 发送引脚。和 `rx` 要么都写，要么都不写 |
| `rx` | `""` | 接收引脚 |
| `loopback` | `False` | 回环模式：自己发的自己收，不上总线 |
| `id` | 1 | 第几个 CAN。F105、F107、F405、F407 等有 CAN1、CAN2，F413、F423 还有 CAN3 |

## 方法

| 方法 | 说明 |
|---|---|
| `send(id, data: bytearray, extended=False) -> bool` | 放进发送邮箱，立刻返回。邮箱满了或者参数不对时返回 `False` |
| `available() -> bool` | 有没有收到的消息在等着读 |
| `id() -> int` | 正在等的那条消息的 ID，没有消息时返回 -1。不会取走消息 |
| `extended() -> bool` | 正在等的那条消息是不是 29 位 ID |
| `read(buf: bytearray) -> int` | 取走消息放进 `buf`，返回长度，没有消息时返回 -1。`buf` 要有 8 字节，放不下的部分丢掉 |
| `@on_rx(priority=8)` | 有消息在等着读时调用处理函数，处理函数是 `def f()` |

ID 默认是 11 位（0 到 0x7FF），`extended=True` 时是 29 位（0 到 0x1FFFFFFF）。一条消息最多 8 字节。

## 没有总线时先试一试

`loopback=True` 不需要收发器，也不需要第二个节点，可以先用它确认程序是对的：

```python
bus = CAN(loopback=True)
```

## 引脚

STM32F103：

| 引脚组 | TX | RX | 可用芯片 |
|---|---|---|---|
| 默认 | PA12 | PA11 | 全部 |
| 重映射 | PB9 | PB8 | 48 脚及以上 |
| 重映射 | PD1 | PD0 | 100、144 脚 |

RX 配置成上拉输入，没接收发器时也能启动。其他芯片的引脚以编辑器的补全和编译报错为准。

## 波特率

编译器按 PCLK1 算出分频，**必须能精确得到写的波特率，否则编译报错**。总线上的节点之间差一点就可能通信失败，所以不取近似值。

| PCLK1 | 能用的常见波特率 |
|---|---|
| 36 MHz（STM32F103 的 72 MHz 配置） | 125k、250k、500k、1M |
| 8 MHz（默认的 HSI） | 125k、250k、500k、1M，但 HSI 不够准，不适合接总线 |

> **接总线时要用外部晶振**（`use_hse = true`），HSI 的误差可能超出 CAN 的要求。

采样点取在 87.5% 附近。在编辑器里悬停在对象上能看到实际的值。

## 发送

- 硬件有 3 个发送邮箱，`send` 把消息放进空的邮箱就返回，按放入的顺序发出。
- **总线上只有一个节点时通信不起来**，这是 CAN 协议规定的：没有别的节点应答，消息会一直重发，邮箱慢慢占满，之后 `send` 就返回 `False`。只有一个节点时用 `loopback`。
- 错误太多时，硬件会自动离开总线（bus off），恢复后自动回来。
- `send` 不等待，在中断里也能用。

## 接收

- 硬件只能存 3 条消息。程序来不及读时，新消息会盖掉最新的那一条，没有提示。总线忙的时候要用 `on_rx`。
- 现在会收下总线上的所有消息，由程序自己看 `id()` 决定要不要。总线很忙时会占用较多的 CPU。
- **`on_rx` 的处理函数必须把消息读走**，否则一返回就又进中断，程序别的事都做不了。

## 注意

- F100、F101、F102、F401、F410、F411 没有 CAN，用了编译报错。
- 每个 CAN 只能有一个对象。
- CAN1 和 CAN2 共用一组过滤器，各用一半。用 CAN2 时，CAN1 的时钟也会打开。F413、F423 的 CAN3 有自己的过滤器。
- STM32F103 的 CAN 和 USB 共用一块内存，不能同时用，中断向量 `USB_LP_CAN1_RX0` 也是共用的。F105、F107 没有这个限制。
