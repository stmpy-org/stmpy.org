# RTC

RTC（实时时钟）是一个每秒加一的计数器，芯片复位后它接着走。在 VBAT 引脚上接电池时，芯片断电期间它也继续走。RTC 还配有几个断电后也能保留数据的备份寄存器。

```python
from stmpy import RTC, UART

rtc = RTC()
uart = UART(1)

@rtc.on_second()
def tick():
    uart.write_int(rtc.now())
    uart.write("\n")

def main():
    if rtc.lost():
        rtc.set(1700000000)     # 时间丢了，重新设置，比如从网络上取
    while True:
        pass
```

要走得准，需要在板子上接 32.768 kHz 晶振，并在 `.spp` 里打开它（见[时钟配置](../../reference/clock/)）：

```toml
[rcc]
use_lse = true
```

## 方法

`RTC()` 没有参数。

| 方法 | 说明 |
|---|---|
| `now() -> int` | 当前的计数，单位是秒 |
| `set(seconds: int)` | 设置计数 |
| `lost() -> bool` | 时间是否不可信：备份域断过电、计数从头开始了，或者时钟没有起振。`set()` 之后变成 `False` |
| `alarm_at(seconds: int)` | 计数到这个值时调用一次 `on_alarm` |
| `save(slot: int, value: int)` | 把 `value` 的低 16 位存进第 `slot` 个备份寄存器 |
| `load(slot: int) -> int` | 读第 `slot` 个备份寄存器，返回 0-65535。编号不存在时返回 -1 |
| `@on_second(priority=8)` | 每秒调用一次处理函数 |
| `@on_alarm(priority=8)` | 到了闹钟的时间调用一次处理函数 |

## 计数的含义

计数从什么时候开始算，由程序自己决定。常见的是 Unix 时间，也就是从 1970 年 1 月 1 日开始的秒数。

- STM32F1 的 RTC 硬件只有一个秒计数器。STM32F4 的硬件是日历，编译器会把它换算成同样的秒计数，所以两种芯片的写法一样。
- 计数是有符号的 32 位 `int`，Unix 时间到 2038 年 1 月会变成负数。
- 目前没有年、月、日的换算。

## 时钟

| 配置 | 时钟 | 精度 | 断电后 |
|---|---|---|---|
| `use_lse = true` | PC14、PC15 上的 32.768 kHz 晶振 | 准，每天差几秒 | 有电池就继续走 |
| 不写 | 芯片内部的 LSI | **很差，可能差三分之一** | 停 |

- **不写 `use_lse` 也能编译，但这时不适合用来看时间**，只能用来粗略地定时。在编辑器里悬停在对象上能看到用的是哪个时钟。
- 用晶振时，PC14、PC15 被占用，不能再当 GPIO。36 脚的封装没有这两个引脚，写 `use_lse` 会编译报错。
- 第一次上电时晶振要几秒才能起振，程序最多等 5 秒。没接晶振或者晶振坏了，程序照常往下跑，但 RTC 不走，`lost()` 一直是 `True`，`set()` 也不起作用。
- 这个等待发生在初始化的时候。用了看门狗时，看门狗要定义在 `RTC` 后面，或者用 `start=False`，否则可能在等晶振的时候就复位了。
- 复位时不会重新配置 RTC，它接着走，也不用再等晶振。改了时钟配置后第一次运行，会清掉时间和备份寄存器。

## 备份寄存器

备份寄存器和 RTC 一样，复位不丢，有电池时断电也不丢，适合存校准值、重启次数这类少量的数据。量大或者没有电池时，用[内部 Flash](../flash/)。

每个寄存器 16 位，`slot` 从 1 开始：

| 芯片 | 个数 |
|---|---|
| STM32F1 的大多数芯片 | 10 |
| STM32F1 的 xE / xG，以及 F105、F107 | 42 |
| F100 的 xE 组，以及 STM32F4 | 20 |

## 中断

- `on_second` 的中断向量是 `RTC`，`on_alarm` 的是 `RTC_Alarm`。
- 闹钟只响一次。要周期性地响，就在处理函数里再调用一次 `alarm_at`。
- `alarm_at` 要在计数到达之前调用，已经过去的时间不会响。
- RTC 闹钟能把芯片从 `stop()` 和 `standby()` 中唤醒，见[低功耗](../power/)。

## 注意

- `set` 和 `alarm_at` 要等 RTC 的慢时钟，大约 100 微秒，在中断里调用也要等这么久。
- 一个程序只能有一个 `RTC` 对象。多个文件要用的话，都 import 同一个对象。
- 复位不会清 RTC，调试时重新下载程序，时间也接着走。
