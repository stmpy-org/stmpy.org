# 看门狗

看门狗在程序卡死或者跑飞时让芯片自动复位。程序要定时"喂狗"，超过设定的时间没喂，芯片就复位。

```python
from stmpy import IWDG

dog = IWDG(1000)

def main():
    while True:
        work()
        dog.feed()
```

芯片有两种看门狗，一般用 IWDG 就够了：

| | IWDG 独立看门狗 | WWDG 窗口看门狗 |
|---|---|---|
| 时钟 | 内部的 LSI，不依赖主时钟 | PCLK1 |
| 精度 | 差，实际的超时是设定值的 2/3 到 4/3 | 准 |
| 最长超时 | 26214 毫秒 | PCLK1 为 36 MHz 时是 58 毫秒 |
| 喂得太早 | 没关系 | 可以设成也复位 |
| 适合 | 兜底，主时钟坏了也能复位 | 检查程序的执行节奏 |

## IWDG

| 参数 | 默认值 | 说明 |
|---|---|---|
| `timeout_ms` | 必填 | 从喂狗到复位的时间，1-26214 |
| `start` | `True` | 程序启动时就开始。`False` 时要调用 `start()` |

STM32F1 的 LSI 标称频率是 40 kHz，实际在 30-60 kHz 之间，每颗芯片都不一样。所以 `IWDG(1000)` 的实际超时在 667 毫秒到 1333 毫秒之间，**要按设定值的 2/3 来喂**，比如每 500 毫秒喂一次。

STM32F4 的 LSI 标称 32 kHz，实际在 17-47 kHz 之间，误差更大，`timeout_ms` 最长约 32768 毫秒。

## WWDG

```python
from stmpy import WWDG

# 两次喂狗要间隔 10 毫秒以上、30 毫秒以内
dog = WWDG(30, min_feed_ms=10)
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `timeout_ms` | 必填 | 从喂狗到复位的时间，上限取决于 PCLK1 |
| `min_feed_ms` | 0 | 离上次喂狗不到这个时间就喂，也会复位。0 表示随时都可以喂 |
| `start` | `True` | 程序启动时就开始。`False` 时要调用 `start()` |

超时是 `PCLK1 / 4096 / 分频` 的整数倍，分频由编译器选，最多 64 步，步长决定了误差。在编辑器里悬停在对象上能看到实际的值。

| PCLK1 | 最长超时 | 最小步长 |
|---|---|---|
| 36 MHz | 58 毫秒 | 114 微秒 |
| 8 MHz | 262 毫秒 | 512 微秒 |

分频器在喂狗时不清零，所以实际的超时可能比设定值少一步。

## 方法

两种看门狗都有：

| 方法 | 说明 |
|---|---|
| `feed()` | 喂狗，重新开始计时 |
| `start()` | 开始运行，从现在开始计时 |

## 启动慢的程序

对象按定义的顺序初始化，`start=True` 时超时从初始化的那一刻算起。后面的初始化和 `main()` 开头的准备工作要在超时之内做完，来不及的话就用 `start=False`，准备好了再开始：

```python
dog = IWDG(1000, start=False)

def main():
    load_config()
    dog.start()
    while True:
        work()
        dog.feed()
```

## 注意

- **看门狗一旦开始就停不下来**，只有复位能让它停。复位后看门狗回到未启动的状态，程序启动时会再开一次。
- 调试器停在断点上时，看门狗也跟着停，不会把芯片复位。
- 不要在定时器中断里无条件地喂狗：主循环卡死了，中断还在跑，看门狗就失去作用了。
- 一个程序只能有一个 `IWDG` 和一个 `WWDG` 对象。要在多个文件里喂狗，就都 import 同一个对象。
- 用了 IWDG 后，低功耗模式也要在超时之前醒来喂狗，见[低功耗](../power/)。
