# 内部 Flash

把芯片内部 Flash 的一部分留出来存数据，比如配置和校准值，断电也不会丢。区域的地址和大小写在代码里，程序改了，数据也还在原来的地方。

```python
from stmpy import Flash

config = Flash(0x0800FC00, 1024)    # 64 KB 芯片的最后一页
data = bytearray(16)

def save() -> None:
    config.erase()
    config.write(0, data)

def main():
    config.read(0, data)
    if data[0] == 0xFF:             # 擦除后全是 0xFF，说明还没存过
        data[0] = 1
        save()
```

## 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `address` | 必填 | 起始地址，必须在页（F4 是扇区）的边界上 |
| `size` | 必填 | 字节数，必须是整页（F4 是整扇区） |

## 方法

| 方法 | 说明 |
|---|---|
| `size() -> int` | 区域的字节数 |
| `read(offset, buf: bytearray) -> bool` | 从 `offset` 开始读满 `buf`，超出区域时返回 `False` |
| `erase() -> bool` | 把整个区域擦成 0xFF，返回是否成功 |
| `write(offset, data: bytearray) -> bool` | 从 `offset` 开始写入 `data`，返回是否成功 |

## 选地址

程序从 Flash 的开头（`0x08000000`）开始连续存放，所以**数据区域要放在 Flash 的最后面**，留给程序的空间才最多。

STM32F1 的 Flash 按页擦除：

| Flash 容量 | 页大小 | 结束地址 | 最后一页 |
|---|---|---|---|
| 16 KB | 1 KB | `0x08004000` | `0x08003C00` |
| 32 KB | 1 KB | `0x08008000` | `0x08007C00` |
| 64 KB（比如 C8T6） | 1 KB | `0x08010000` | `0x0800FC00` |
| 128 KB | 1 KB | `0x08020000` | `0x0801FC00` |
| 256 KB | 2 KB | `0x08040000` | `0x0803F800` |
| 384 KB | 2 KB | `0x08060000` | `0x0805F800` |
| 512 KB | 2 KB | `0x08080000` | `0x0807F800` |
| 768 KB | 2 KB | `0x080C0000` | `0x080BF800` |
| 1 MB | 2 KB | `0x08100000` | `0x080FF800` |

F105、F107 的页不管容量多大都是 2 KB。

STM32F4 的 Flash 分成大小不等的扇区，地址和大小都要按整扇区来：

| 扇区 | 大小 | 起始地址 |
|---|---|---|
| 0-3 | 每个 16 KB | `0x08000000` 起 |
| 4 | 64 KB | `0x08010000` |
| 5 及以后 | 每个 128 KB | `0x08020000` 起 |

64 KB 的芯片只有扇区 0-3，128 KB 的到扇区 4 为止。2 MB 的芯片分成两个 bank，从 `0x08100000` 开始又是同样的分法。比如 1 MB 芯片的最后一个扇区是 `Flash(0x080E0000, 131072)`。

规则：

1. 地址和大小必须对齐到页或扇区，超出芯片的 Flash 时编译报错。换成页大小不同的芯片时，报错会提醒你改。
2. 多个区域不能重叠。
3. **程序必须在最靠前的那个区域之前结束**，放不下时链接报错 `region FLASH overflowed`。

编译输出的 Flash 用量，是相对于程序能用的那一部分算的：

```
flash: 4196 / 60416 bytes (6.9%), the last 5120 kept for data
```

## 写入规则

Flash 只能把 1 写成 0，要改回 1 只能擦除，而且一次要擦一整页。所以：

1. **写之前要先擦除，写过的地方不能再写。** `write` 会先检查，要写的范围里有任何地方写过，就什么都不写，返回 `False`。
2. `offset` 必须是偶数，硬件按 2 字节写入。
3. `data` 的长度是奇数时，最后一个字节后面补一个 0xFF，这 2 个字节之后也不能再写。
4. 超出区域时什么都不写，返回 `False`。

在一块擦好的区域里，可以分多次写不同的位置。比如记日志时一条接一条往后写，写满了再擦。

## 寿命和断电

- **每页大约能擦 1 万次。** 经常变化的数据不要每次都擦：一秒存一次的话，不到 3 小时就用掉 1 万次。可以把新数据往后追加，写满了再擦；少量数据也可以用 [RTC](../rtc/) 的备份寄存器。
- 擦除或写入时断电，这块数据可能是坏的。重要的数据要自己加校验，比如用 [CRC](../crc/)，并且存两份轮流写。

## 时间

| 操作 | 时间 |
|---|---|
| 读 | 和读内存差不多 |
| 写 | 每 2 字节约 50 微秒 |
| 擦除 | F1 每页约 20-40 毫秒；F4 的一个 128 KB 扇区要一秒以上 |

**写入和擦除时 CPU 会停住**，因为程序本身也在 Flash 里。中断也要等着，定时器的处理函数会迟到，`delay_ms` 也会变慢。DMA 不受影响，`rx_buffer` 照常收数据。看门狗的超时要留出这段时间。

`erase` 和 `write` 不能在中断里调用，编译时报错。

## 多个区域

可以定义多个 `Flash` 对象，各自擦除，互不影响：

```python
config = Flash(0x0800FC00, 1024)
records = Flash(0x0800EC00, 4096)
```

对象的定义顺序不影响地址。改了 `address` 或 `size`，读到的就是另一块数据，原来存的不会跟着搬过去。

## 注意

- 重新下载程序时，下载工具通常只擦要写的页，数据还在；但整片擦除会把它清掉。
- STM32F4 上用 `Flash` 时，HCLK 至少要 1 MHz。
